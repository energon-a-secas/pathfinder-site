Checkout 500s: investigation

The walkthrough's case: checkout fails for some people, nobody knows why, and you want a coding assistant to read the repository instead of inventing a plausible theory. Twelve blocks that separate the symptom from the beliefs around it, with the reproduction as the first boundary. The walkthrough builds it from nothing.

12 blocks, Investigate mode

Your own bug, not this one? : the same shape without the checkout story, 13 blocks, framed for a repository you have open and told to reproduce before theorising.

Inherit a codebase

Somebody left, the repository is yours now, and the first wrong move is trusting what the README says. This map works from an unknown repository to a first safe change: what is believed, what is actually verified, and the questions whose guessed answers cost the most.

13 blocks, Investigate mode

Migrate a system

Old to new with a way back at every step. The part most migrations skip is the reconciliation loop: old against new, per entity, every day, with a threshold that blocks the next phase. This map carries it, plus the risks that live at the cutover and an end that only fires when the old system is off, not merely unused.

15 blocks, Plan mode

Plan a recurring report

Reports that go out every sprint and every quarter, mapped the way the six steps read: the goal they serve, who reads each one, the lead time that says whether it works, and the difference between the work done once (building the scheduler, an Implementation) and the run that repeats (a Process, started by a Trigger). One weekly report reaches nobody on the map, and the gap check says so: that is the question worth asking before automating it.
